# Container Observability

## Overview

In this laboratory activity, I learned how to deploy and monitor a web server using Docker. I also practiced sending HTTP requests, checking application logs, and observing container resource usage. These activities helped me understand how a Cloud Operations Engineer monitors a web application and identifies possible errors.

## Nginx Container Deployment

I deployed an Nginx web server in a Docker container named `client-website`. The container was configured to run in the background, with host port `8080` mapped to container port `80`. This allowed me to access the Nginx website through my local environment.

The Docker command used was:

```bash
docker run -d --name client-website -p 8080:80 nginx
```

I used the `docker ps` command to verify that the container was running.

## HTTP Traffic Generation

I used the `curl` command to send three HTTP requests to the Nginx web server.

```bash
curl http://localhost:8080
```

All three requests successfully returned the default Nginx welcome page with an HTTP `200` status code. This confirmed that the web server was responding correctly to incoming requests.

To test how the server handled an unavailable page, I also sent a request using the following command:

```bash
curl http://localhost:8080/hidden-admin-page
```

The server returned an HTTP `404 Not Found` response because the requested page did not exist. This demonstrated how the web server handles requests for unavailable resources.

## Application Logging

### Nginx Container Logs

I used the following command to view the logs generated by the container:

```bash
docker logs client-website
```

The logs showed the Nginx startup process, including its configuration, initialization, and worker process creation. They also recorded the HTTP requests sent to the server.

The three requests to the homepage returned status code `200`, while the request to `/hidden-admin-page` returned status code `404`. The error log also indicated that Nginx could not find the requested file in its web directory.

### Importance of Application Logs

Application logs are useful for monitoring server activity and identifying errors. They provide information about incoming requests, response status codes, and application events. By examining these records, administrators can troubleshoot problems, verify whether a service is working correctly, and better understand the behavior of a web application.

## Real-Time Container Metrics

I used the `docker stats` command to monitor the resource consumption of my Nginx container. This command displays information about CPU usage, memory consumption, network input and output, block input and output, and the number of processes running inside the container.
